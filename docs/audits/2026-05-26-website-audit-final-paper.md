# Website Audit Final Strategy Paper

Date: 2026-05-26
Site: https://onyxaistudio.digital
Workflow: Website Audit
Deliverables: four specialist audits plus this final paper and a detailed fix plan

## Executive Summary

The four-agent audit found that Onyx AI Studio has moved from a credibility-building website into an early sales platform for premium AI operations work. The main technical and UX blockers have been reduced. The site now has a clearer mobile path, staged lead capture, Supabase-backed lead persistence, Resend notifications, a named AI Operations Review, stronger pricing, better proof context, and improved crawl/AI discovery surfaces.

The next problem is sharper: Onyx must convert this credible site into a focused sales system. The top priorities are to productize the AI Operations Review, create one strong granite/countertop proof path, expose a minimum operator lead pipeline, make the broad portfolio easier to use as capability evidence, and reduce frontend performance risk.

## Consensus Strengths

- The site is credible enough to support premium AI operations sales conversations.
- Mobile conversion access is much stronger than before.
- Technical SEO basics are healthy across sampled pages.
- The sitemap, robots policy, and `llms.txt` give search and AI systems usable discovery paths.
- The AI Operations Review is the right conversion concept.
- Supabase lead persistence and Resend notifications mean the form is now real infrastructure.
- The granite/countertop quote-intake path is the strongest beachhead because it connects proof, buyer pain, and implementation specificity.
- The visual identity is an asset and should be refined rather than replaced.

## Consensus Weaknesses

- The AI Operations Review is still not concrete enough on the live sales surface.
- Proof is capability-heavy and needs more workflow evidence: intake maps, sample lead records, implementation boundaries, and screenshots.
- The portfolio is intentionally broad because buyers may arrive looking for a specific kind of system. It should stay broad, but needs clearer signposting so visitors can quickly map demos to the kind of build they want.
- The Supabase pipeline is structurally ready but not operator-visible.
- Homepage script, reveal, and animation cost remain a trust and performance risk.
- External authority and entity signals are still early.
- Delivery operations need better SOP coverage for the actual premium promise.

## Disagreements And Cautions

- The frontend and UI/UX agents warned against broad redesign. The current identity works; the next step is sharper content, proof, and performance.
- The SEO/GEO agent warned that pipeline visibility should not outrank public proof and Review packaging for the next website sprint, because search and AI discovery need externally visible content.
- The business agent warned that generic authority building should not happen before the offer is sharpened. Buyers need to understand the Review output and why Onyx is credible for their specific problem.
- All agents agreed not to overreact to Search Console showing low indexed sitemap counts yet, because live crawlability is healthy and impressions exist.

## Recommended Strategy

Focus the next sprint on one sales path: granite/countertop quote-intake systems powered by the AI Operations Review. The site should make a buyer understand, within one path, what the Review is, what it produces, how their intake problem maps to a system, what proof Onyx has, what happens after submission, and how Onyx handles their data.

Do not remove the broad portfolio or treat it as a product catalog problem. Keep it as capability evidence, but add better signposts from buyer problems to relevant demos. Build the public Review package and flagship proof path first, then expand SEO/GEO content around the same beachhead.

## 30-Day Action Plan

1. Add a public AI Operations Review package block to `/contact`, the homepage CTA area, and the Review insight.
2. Include deliverable, turnaround, format, free/paid/credited status, after-submission path, fit criteria, not-fit criteria, and privacy/data-handling language.
3. Build the granite/countertop proof path around the Countertop Estimate Tool, quote-intake pain, sample lead record, before/after workflow, and Review CTA.
4. Add portfolio signposts so buyers can jump from common build intents to relevant demos without hiding the full library.
5. Add Escape/focus-return behavior to the mobile menu and tighten form validation/focus cues.
6. Reduce avoidable homepage script and reveal cost.

## 60-Day Action Plan

1. Create a minimum lead pipeline view for the operator: priority, status, owner, next action due, notification status, source/campaign, contacted/booked/proposal/closed, and estimated value.
2. Add delivery SOPs for discovery, source intake, assistant rules, Retell setup, Supabase schema, testing, launch, monitoring, monthly review, privacy/retention, and offboarding.
3. Expand the beachhead content cluster across the AI integration service, Countertop case study, AI Operations Review insight, and a niche landing page.
4. Add external entity reinforcement through consistent profiles, citations, relevant backlinks, and source references.
5. Add better proof artifacts: screenshots, sample review output, sample lead summary, implementation timeline, and implementation boundaries. Do not require ROI math on the site.

## 90-Day Action Plan

1. Use actual pipeline data to refine scoring, qualification, follow-up timing, and offer language.
2. Add outcome data when real client or campaign results are available.
3. Expand from the granite/countertop beachhead into the next adjacent service niche only after the first path is commercially clear.
4. Review Search Console indexing, impressions, and query data; update sitemap/content priorities based on observed behavior.
5. Create a monthly site/business audit cadence using the Website Audit workflow.

## Priority Backlog

- Productize AI Operations Review on public pages.
- Build granite/countertop flagship proof path.
- Add visible lead pipeline view.
- Improve portfolio signposting while preserving the broad demo library.
- Add privacy and data-handling trust copy near forms.
- Reduce homepage JavaScript and reveal cost.
- Harden mobile menu keyboard behavior.
- Add form required cues and focus/error polish.
- Expand beachhead SEO/GEO content.
- Add delivery SOPs for premium AI operations implementation.
- Fix documentation drift around contact form requirements.
- Monitor Search Console before treating low indexed counts as a technical emergency.

## Success Metrics

- Review form completion rate.
- Qualified Review submissions per week.
- Time from submission to first follow-up.
- Percentage of leads with owner, status, next action, and due date.
- Booked calls from Review submissions.
- Proposal and closed-won rate from Review submissions.
- Search Console impressions, indexed pages, and click growth for the beachhead pages.
- AI search/agent retrieval accuracy for Onyx, AI Operations Review, and granite/countertop quote-intake topics.
- Homepage Core Web Vitals and script weight trend.
- Proof-path engagement: visits, scroll depth, CTA clicks, and form starts.

## Final Recommendation

Treat the next phase as sales-system tightening, not a redesign. Onyx has enough technical foundation and visual credibility to sell. The highest-leverage work is to make the AI Operations Review concrete, make the granite/countertop proof path undeniable, and make the lead pipeline operationally visible.
