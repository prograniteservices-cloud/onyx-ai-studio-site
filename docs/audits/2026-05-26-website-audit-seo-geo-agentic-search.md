# Website Audit: SEO, GEO, And Agentic Search

Date: 2026-05-26
Site: https://onyxaistudio.digital
Workflow: Website Audit
Agent role: SEO / GEO / Agentic Search Auditor
Original score: 85/100
Roundtable-adjusted score: 86/100

## Summary

Technical SEO is no longer the main bottleneck. Sitemap routes are healthy, sampled pages are indexable, robots and `llms.txt` are in place, schema and entity signals are stronger, and the current site is fit for crawl and AI discovery.

The remaining SEO/GEO bottleneck is authority, specificity, citability, proof depth, and a disciplined niche path. The site needs externally visible reasons for Google, AI search systems, and buyers to associate Onyx with a specific operational problem.

## Strengths

- The correction sprint fixed several major gaps: `/about`, mobile CTA/menu, route constraints, no dead service CTA, contact form improvements, pipeline fields, and removal of unnecessary Framer dependency from the main path.
- Sitemap coverage is broad and current.
- Sampled routes returned 200, were self-canonical, indexable, and had one H1.
- `robots.txt` allows major search and AI crawlers, including Google/Bing and common AI crawlers.
- `llms.txt` includes the Review, Countertop, VapeOS, Pricing, and About surfaces.
- Structured data and entity signals are stronger.
- Internal linking is coherent.
- Main pages have better content depth than before.
- Search Console showing low indexed counts should be monitored, but impressions exist, so crawlability is not dead.

## Weaknesses And Risks

- Search Console still needs monitoring because sitemap indexing lags the technical readiness.
- Query footprint is early and clicks are not yet material.
- Secondary pages are thinner than the main commercial surfaces.
- External entity strength is weak and can be confused with generic AI studio language.
- Proof is still more capability-heavy than outcome-heavy.
- FAQ markup may help extraction, but should not be overvalued as a Google rich-result strategy.
- Uniform sitemap `lastModified` values and unused large public assets are cleanup opportunities.
- Homepage script and reveal pressure can indirectly affect search performance through UX and Core Web Vitals risk.

## Priority Recommendations

1. Productize the AI Operations Review publicly with price/free status, format, inputs, deliverable, timeline, fit criteria, and next step.
2. Build one flagship granite/countertop proof path with workflow before/after, quote-intake artifacts, an example lead summary, screenshots, and CTA.
3. Expand priority SEO/GEO pages around the beachhead: `/services/ai-integration`, `/case-studies/countertop-estimator`, `/insights/what-is-ai-operations-review`, and a niche landing page.
4. Add privacy/trust and platform-source sections: data handling, human escalation, Retell/Supabase roles, and official source references where appropriate.
5. Reduce homepage and reveal script pressure and harden menu/form accessibility so mobile visitors and crawlers see a fast, stable primary path.
6. Monitor Search Console for 7-14 days before treating low indexed counts as a new technical emergency.
7. Reinforce external entity signals through profiles, citations, relevant backlinks, and consistent niche language.

## Evidence Gathered

- Reviewed sitemap, robots, `llms.txt`, route metadata, page indexability, schema posture, internal linking, and content structure.
- Considered Search Console context: low submitted indexed count, but live technical checks and impressions indicate discoverability exists.
- Compared findings with frontend, UI/UX, and business-management audits.

## Roundtable Position

The agent agreed that crawlability is healthy and that the next gains are commercial proof, entity clarity, niche specificity, and Review productization.

The agent cautioned that operator pipeline visibility should not outrank public proof and Review packaging for the next website sprint. It matters, but SEO/GEO gains depend on externally visible specificity and citability.
